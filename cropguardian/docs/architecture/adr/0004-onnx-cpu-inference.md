# ADR 0004 — Vision inference as ONNX int8 on CPU inside the API

**Status:** Accepted · **Date:** 2026-10-16 · **Deciders:** Taeen, Apon

## Context
Free Render instances have limited memory and no GPU; Render does not publish exact free
RAM/CPU on its free-tier page [R1], so we design for a small footprint. PyTorch + torchvision
alone is a multi-hundred-MB install.

## Decision
Train in PyTorch on free Colab/Kaggle GPUs. Export the selected model to ONNX, apply dynamic
int8 quantisation, verify parity (top-1 agreement vs FP32 on the validation set, recorded in
the model card). Serve with `onnxruntime` (CPU) — loaded once at startup, shared session.
Image pre-processing with Pillow + NumPy (no torch at runtime).

## Alternatives rejected
- **PyTorch at runtime** — image size and RAM.
- **Hugging Face Inference API / Spaces** — another sleeping dependency and data leaving our boundary.
- **TensorFlow.js in the browser** — attractive for offline, but model download size on slow
  networks and low-end phones; kept as a future option (same ONNX via onnxruntime-web).

## Consequences
+ Small image, predictable latency, no GPU needed. − Quantisation can drop accuracy →
parity gate. − Grad-CAM needs gradients → heat-maps generated by the training stack; runtime
uses a cheaper occlusion/saliency approximation or none, stated honestly in the UI.
