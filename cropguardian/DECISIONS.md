- **D-036 - 2026-11-20 - Unique asyncpg prepared-statement names (hosted login/demo were broken).** Supabase Postgres logs showed `prepared statement "__asyncpg_stmt_N__" already exists` and the first hosted demo sign-in returned 500. Cause: the Supavisor transaction pooler keeps server connections (and their named statements) across app restarts; a new process restarts asyncpg's counter and collides. Fix: `connect_args["prepared_statement_name_func"]` returns `__asyncpg_<uuid4>__` (SQLAlchemy's documented recipe), in `app/db/session.py`. Reproduced locally with PgBouncer 1.26 in transaction mode (`max_prepared_statements = 0`): after an abrupt process exit a fresh process hit 27 `DuplicatePreparedStatementError`s without the fix and 0 with it.
